Install

An assistant lands in an unfamiliar project and needs to choose where to look. Without a useful search term, the first step is the map.

The idea in one picture

Kimono 0.9.6 adds aikido_structure, a read-only tool that returns the file tree of your snapshot, under the same ignore rules as the rest of Kimono. Each file carries a type and an idx flag telling whether Kimono indexes it, so the assistant sees at once what a search can reach and what it cannot.

What you ask your assistant

In VS Code, you open your assistant’s chat with Kimono connected and write, as you would to a colleague:

The assistant answers within seconds, without having opened a single file. It first shows src: an api/ folder and an index.ts file. It then points out that two files are out of reach of search: an exclusion file (.gitignore) and an image (logo.png). You already know what a search can find, and what it never will.

You follow up: “Give me the whole tree, in compact form”. This is what appears, twelve lines for the entire project:

Under the hood

Behind your question about unindexed files, the assistant called aikido_structure with idx: 0. This is the raw reply it received:

  • 8files in the example project
  • 6of them indexed; 2 are not (an ignore file and an image)
  • 12lines for the whole tree in text form

The answer also carries a version marker v. Pass it back as since and, if nothing changed, the tool replies {"unchanged":true} instead of resending the tree.

To remember

Types come from a built-in table that covers everything Kimono indexes plus common files it does not. You can override it with a rules file (KIMONO_TYPES_FILE). The tool describes the files of your snapshot; it does not read them.

Try it

  1. Update Kimono to 0.9.6 or newer and open a snapshot with aikido_snapshot.
  2. Call aikido_structure on the root, then scope it with path and depth.
  3. Search where the map points. The full list of options is in the changelog.
