How much of your workflow really needs a model?

Moving steps from a prompt to a script makes them predictable and free to rerun. AI-KIDO 1.5.5 measures that shift: each step is classed, and the workflow gets an automated share you can raise.

Camille’s release notes workflow works. Every release, an agent drafts the notes, another opens every link, and she proofreads. But each run costs tokens and a few minutes, and the link check sometimes reports a different result for the same page. She asks herself a simple question: in this chain, which steps truly need a model?

The idea in one picture

The industry has several names for this shift. You speak of compiled AI or workflow distillation when the logic of a prompt is frozen into ordinary code that runs the same way every time, at no model cost. DSPy and GenAIScript program prompts with typed inputs and outputs instead of free text.

When a model stays in the loop, constrained decoding keeps its answer usable by a script. Claude and OpenAI both offer structured outputs that follow a JSON schema.

AI-KIDO puts a measure on that path. Each step of a workflow falls into one of three classes, and the score is their weighted average.

  • Deterministic · 1A script, a command, or a decision taken by the engine itself, such as a choice on a value. Same input, same output.
  • Assisted · 0.5A model that must return a validated output schema. It still writes, but its answer can be checked by a script.
  • Open · 0A free prompt, or a human decision. Valuable, but neither predictable nor free to rerun.

What Camille does: score, then distill

She asks for the score of the version she uses today. The calculation calls no model: it reads the workflow and explains each step.

  1. You
    /workflow-score release-notes
  2. Assistant
    Automated share of release-notes 1.0.0: 0.25 (static method).
    Draft: open, agent with a prompt. Check links: open, agent with a prompt. Links OK?: deterministic, choice on a value. Human review: open, human decision.

The answer surprises her: checking links does not need a model at all. A short script can open each URL and count the broken ones. The draft does need a model, but it can return its sections in a schema that a script verifies. She creates version 1.1.0 with these two changes and keeps the human review.

The goal is not 100 %

The human review stays open, and that is deliberate. The score does not ask you to remove judgment; it shows where a model is used by habit rather than by need. A step that decides what a release says is worth a model or a person. A step that counts broken links is worth a script.

Remember

The score is static: it reads the definition, calls no model and gives no cost estimate. The same workflow always gets the same score, so a change in the score always comes from a change in the workflow.

In the Core Agent development preview, a second measure follows real runs: it counts the steps actually executed by a script and estimates the tokens avoided, an estimate and never an invoice. The static score tells you what a workflow allows; the measured share tells you what it did.

Two rules behind the score

Version 1.5.5 adds two hard points that every AI-KIDO agent follows. The first, Code Economy, makes the agent stop at the cheapest route that meets the need: no code, then an existing asset, then the platform, and only then new code. Before writing the link checker, an agent first looks for a script the project already has.

The second, Agent Economy, treats tokens and retries as a budget. A failed call proves nothing about the data it targeted: if the link checker times out, the step is reported as not verified, never as “no broken link”.

For the other side of the same idea, letting scripts do what a script does exactly, see our article on deterministic tools.

Try it

  1. Install the 1.5.5 CLI: npm install -g @aikido-method/cli@1.5.5, or follow the installation page.
  2. Write or open a workflow with /workflow-new, then look for steps that a script could run or that could return a schema.
  3. With a Tatami Core Agent configured, type /workflow-score before and after your change, and keep the human steps that matter.
