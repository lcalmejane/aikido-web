Compile your commands: from prompt to script

A command, a skill or an agent written in prompts can be compiled: its repeatable steps become tested, shared scripts, and its automated share is measured before and after.

Install

Camille’s team wrote two commands for its assistant: /release-notes and /publish-docs. Both work. But both ask a model to check the same links, every time, at the cost of tokens and with results that vary from one run to the next. She wonders which of these steps really need a model, and whether the others could be frozen once and for all.

The idea in one picture

The industry has several names for this move. You speak of compiled AI or workflow distillation when the logic of a prompt is frozen into ordinary code that runs the same way every time, at no model cost. DSPy even uses the word: it compiles declarative model calls into optimized pipelines.

When a model stays in the loop, constrained decoding keeps its answer usable by a script. Claude and OpenAI both offer structured outputs that follow a JSON schema; GenAIScript scripts prompts in JavaScript.

AI-KIDO applies this to what you already write: commands, skills and agents. Each step falls into one of three classes, and the automated share is their weighted average.

  • Deterministic · 1A script or a command written in the step. Same input, same output, no model.
  • Assisted · 0.5A model that must return a validated output schema. It still writes, but a script can check it.
  • Open · 0A free prompt, a human decision, or a rule the agent must respect. Valuable, but not a script.

What Camille does: compile two commands

In Tatami, she asks for both commands to be compiled at once. The compiler cuts each definition into steps and classes them. For the open steps, a model proposes a command; the compiler then checks the result before accepting it, and the team reviews the change like any other.

  1. You
    Compile /release-notes and /publish-docs.
  2. Assistant
    Both compiled, version 1.0.0 → 1.0.1.
    /release-notes: 0 → 0.5. Link check and pull request count now run as scripts; the draft and the proofreading stay with the model and the maintainer.
    /publish-docs: 0.33 → 0.67.
    3 scripts generated, 1 shared: the link check is the same in both commands, so they call the same script.

She opens /release-notes. Nothing has disappeared: each step keeps its sentence, and the steps that became scripts now say which one they call.

Each generated script replays exactly the command it replaces, can show it without running it (--print) and comes with its test. Its name carries a fingerprint of the command: two definitions that do the same thing end up calling the same script.

What the score shows, up to the agent

The team’s release agent does little by itself: it chooses the version number with the maintainers, then calls the two commands. Its automated share is the average of its own steps and of what it calls. It therefore rises without anyone touching it.

Remember

A compilation is refused if it changes the number of steps, if a script does not replay the original command, or if the automated share drops. The version is bumped only when the compilation is accepted.

On AI-KIDO’s own commands

We ran the compiler on ten public commands of version 1.5.5. Nine were compiled into eleven scripts. /aikido-review was refused, rightly: it has no step a script can run, since reviewing on evidence is a judgment.

  • 9/10public 1.5.5 commands compiled
  • 11scripts generated, each with its test
  • 0score changes: their commands were already written as commands

The scores did not move, and that teaches something. Many open steps in these commands are guardrails, such as “Do not change any file unless the user asks”. No script replaces a rule of conduct; the goal is not 100 %, but to stop paying a model for what a command does exactly.

And for workflows

Workflows have their own score, /workflow-score, which classes each state. On the release notes workflow from our 1.5.5 article, turning the link check into a script and giving the draft an output schema raises it from 0.25 to 0.63, with the human review left open on purpose.

Two rules behind the compiler

Version 1.5.5 adds two hard points that every AI-KIDO agent follows. Code Economy makes the agent stop at the cheapest route: an existing command or script before new code, which is why the compiler reuses a shared script rather than writing a second one.

Agent Economy treats tokens and retries as a budget, and a failed call proves nothing. If the link script times out, the step is reported as not verified, never as “no broken link”. For the general principle, see our article on deterministic tools.

Try it

  1. Install the 1.5.5 CLI: npm install -g @aikido-method/cli@1.5.5, or follow the installation page.
  2. In your commands and skills, write the repeatable steps as real commands in backquotes: they are deterministic from the start.
  3. With a Tatami Core Agent configured (development preview), compile your commands, skills or agents, then compare the automated share before and after.
