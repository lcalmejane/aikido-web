Kimono MCP: the Memory Bank opens up to connected clients

In AI-KIDO mode, Kimono serves the same documents, commands, personas and workflows to any MCP client. One shared base, a few documented ways to connect to it.

Your team keeps its rules, personas and workflows in an AI-KIDO Memory Bank. One member uses VS Code, another a command-line assistant, and a coding agent runs in the cloud. Each of them needs the same knowledge, and none of them should get a stale copy.

The idea in one picture

Kimono is an MCP server. In AI-KIDO mode it takes a root folder containing prompts/index.md or index.md and exposes that Memory Bank through the same small set of tools to every client that speaks MCP. The method becomes something connected clients can search, not something each of them has to be taught.

Choose the mode

RAG is the default, and the presence of an AI-KIDO index does not switch modes by itself. You choose explicitly, on the surface you configure:

Three ways to connect

  • IDE extension (recommended): install it from the Visual Studio Marketplace in VS Code or a compatible IDE.
  • Docker server: a shared corpus for several MCP clients, including GitHub Copilot cloud agent, through the /mcp endpoint.
  • Native install from source: a local stdio server for an MCP client that supports it.

For the cloud agent, you open your repository settings, Copilot section, and paste the MCP configuration that declares a remote server. The token is stored as an Agents secret, never in the file.

Watch for

A server on your laptop is not visible to a cloud agent. Local Docker Compose binds to loopback and is not directly reachable by GitHub. The endpoint must be reachable over HTTPS, protected by authentication, and point at a checkout the server can read.

Try it

  1. Pick a connection from the Kimono repository README.
  2. Set AI-KIDO mode and point the server at a folder holding your Memory Bank.
  3. Ask your assistant a question your base can answer. More on the Kimono page.
