Install

You change one rule in your project's Memory Bank, and now several assistants must follow it. Until 1.5, that meant copying files by hand into whichever folder each tool expects, and hoping nothing drifted. Version 1.5 removes that chore.

The idea in one picture

AI-KIDO keeps a single canonical source: the hard_points/ folder of the method repository. A build step generates, for each assistant, the files that assistant understands natively. Claude Code gets a marketplace plugin with slash commands, Skills and agents. GitHub Copilot, Codex, Kiro, Zoo Code, Roo Code and Antigravity get workspace files. Claude Cowork gets a plugin you upload to your account. That makes nine packages from one source.

Because the wrappers are generated rather than written by hand, they cannot quietly diverge: every enabled assistant gets a native wrapper for the same 15 agents.

What you do: preview before installing

You pick your assistant on the Install page, then copy the two commands shown into a terminal opened on your project. An installation adds a few hundred files, so the installer never starts by writing. It starts by computing a plan, which you read before deciding. Here is the walkthrough for Claude Code, from the 1.5.2 distribution tag:

On an empty Git project, the terminal tells you 170 files to create, no conflict, no blocked path, and that the plan is ready. You scroll through the list of paths: everything sits in the folders Claude Code expects, and nothing has been written yet.

  • 170files planned for Claude Code in STANDARD mode
  • 0conflicts or blocked paths on an empty project
  • 9assistants packaged from one source

The apply step refuses to run unless you pass --confirm followed by this exact plan id. You approve the plan you read, not one that merely looks similar.

Updates and removal keep your work

Version 1.5.0 added package-based updates with a three-way merge, explicit conflicts, backups and recovery, plus an uninstall that removes only the adapter files. Your Memory Bank under prompts/ stays where it is. The /skill-manage command also relies on a deterministic engine now to search, install and update skills from a catalog and from trusted external sources.

Try it

  1. Pick your assistant in the installation page.
  2. Run the plan command and read the paths it lists.
  3. Apply with --confirm and the plan id. The full list of changes is in the changelog.
