Installer

Vous modifiez une règle de la Memory Bank de votre projet, et plusieurs assistants doivent maintenant la suivre. Jusqu’à la 1.5, cela voulait dire copier des fichiers à la main dans le dossier attendu par chaque outil, en espérant que rien ne dérive. La version 1.5 supprime cette corvée.

L’idée en une image

AI-KIDO garde une seule source canonique : le dossier hard_points/ du dépôt de la méthode. Une étape de génération produit, pour chaque assistant, les fichiers qu’il comprend nativement. Claude Code reçoit un plugin de marketplace avec commandes slash, Skills et agents. GitHub Copilot, Codex, Kiro, Zoo Code, Roo Code et Antigravity reçoivent des fichiers d’espace de travail. Claude Cowork reçoit un plugin à téléverser dans votre compte. Cela fait neuf paquets issus d’une seule source.

Comme les wrappers sont générés et non écrits à la main, ils ne peuvent pas diverger en silence : chaque assistant activé reçoit un wrapper natif pour les mêmes 15 agents.

Ce que l’on fait : prévisualiser avant d’installer

Vous choisissez votre assistant dans la page Installation, puis vous copiez les deux commandes affichées dans un terminal ouvert sur votre projet. Une installation ajoute quelques centaines de fichiers : l’installateur ne commence donc jamais par écrire. Il commence par calculer un plan, que vous lisez avant de décider. Voici le déroulé pour Claude Code, depuis le tag de distribution 1.5.2 :

Sur un projet Git vide, le terminal vous annonce 170 fichiers à créer, aucun conflit, aucun chemin bloqué, et que le plan est prêt. Vous parcourez la liste des chemins : tout est dans les dossiers attendus par Claude Code, rien n’est encore écrit.

  • 170fichiers prévus pour Claude Code en mode STANDARD
  • 0conflit ou chemin bloqué sur un projet vide
  • 9assistants packagés depuis une seule source

L’étape d’application refuse de s’exécuter sans --confirm suivi de cet identifiant de plan exact. Vous validez le plan que vous avez lu, pas un plan qui lui ressemble.

Mises à jour et retrait respectent votre travail

La version 1.5.0 a ajouté les mises à jour par paquet avec fusion à trois voies, conflits explicites, sauvegardes et reprise, ainsi qu’une désinstallation qui ne retire que les fichiers d’adaptation. Votre Memory Bank sous prompts/ reste en place. La commande /skill-manage s’appuie aussi désormais sur un moteur déterministe pour chercher, installer et mettre à jour des compétences depuis un catalogue et des sources externes de confiance.

À essayer

  1. Choisissez votre assistant dans la page Installation.
  2. Lancez la commande de plan et lisez les chemins qu’elle liste.
  3. Appliquez avec --confirm et l’identifiant du plan. La liste complète des changements est dans le changelog.
