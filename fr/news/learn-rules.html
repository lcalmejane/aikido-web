/learn : vous corrigez, elle propose, vous validez, vos agents s’en souviennent

L’apprentissage fait partie d’AI-KIDO depuis le début. /learn en facilite l’usage : un raccourci de commande transforme vos corrections en règles validées. Découvrez-le dans l’interface Tatami Agent.

Installer

Vous corrigez votre assistant pour la deuxième fois sur le même point : le mauvais fichier, un contrôle oublié, une convention ignorée. La semaine prochaine il recommencera, parce que la leçon n’a vécu que dans cette conversation. Or AI-KIDO n’a jamais été une méthode figée : depuis l’origine, ses points durs, ses Truth Tables et les règles de la Memory Bank sont écrits, relus et corrigés par les personnes du projet, et les agents les lisent pour s’y conformer. C’est cela, l’auto-apprentissage d’AI-KIDO : la base de connaissance évolue avec ce que vous lui apprenez.

Vous guidez, la commande vous assiste

La règle d’apprentissage n’est pas née avec /learn. L’introspection et l’amélioration continue font déjà partie des fondements d’AI-KIDO, documentés dans la première version publique de référence. Vous enseignez, corrigez et enrichissez la base ; la commande donne à cette pratique un chemin plus court et réutilisable.

/learn est arrivée en renfort avec AI-KIDO 1.5.2. Elle ne remplace pas ce mécanisme et ne décide rien seule : elle vous aide à guider vos agents et votre base de connaissance en transformant vos corrections de la session en règles courtes. Vous les relisez, vous choisissez celles que vous gardez, et elles sont rangées dans prompts/gen/learned.md, un fichier lu au début de chaque demande.

Ce que vous tapez, ce que vous voyez

Une commande nommée devient aussi un raccourci dans l’interface. Dans l’interface de développement de Tatami Agent ci-dessous, le bouton Learn se trouve à côté du compositeur. Son infobulle explique l’action d’apprentissage : relire le contexte, identifier une erreur et proposer une règle pour la base de connaissance. La conversation, les suggestions de commandes et la visualisation interactive restent visibles autour : l’apprentissage s’inscrit dans le même espace où vous échangez, examinez et guidez l’assistant. Vous pouvez aussi saisir /learn dans le compositeur pour sélectionner la commande du projet ; choisir cette suggestion ne lance aucun travail et n’enregistre aucune règle.

C’est un aperçu de Tatami Agent, l’interface CLI LLM d’AI-KIDO en développement. Le CLI npm public de la méthode installe et met à jour la Memory Bank : il s’agit d’un autre outil. La même commande écrite peut guider un assistant qui charge les instructions AI-KIDO, chaque hôte proposant sa propre interface.

Après une session où vous avez dû reprendre l’assistant, vous tapez /learn, avec si vous le souhaitez un indice entre guillemets. L’assistant relit la conversation et vous présente ses propositions, puis vous demande lesquelles garder. L’échange ci-dessous est une illustration.

  1. Vous
    /learn "j’ai dû rappeler de lancer les tests avant de pousser"
  2. Assistant
    J’ai relu la session et je propose une règle : L-build-001, lancer les tests avant de pousser. Elle s’applique avant tout push vers la branche principale et demande de lire le résultat des tests. Validez-vous ? y accepte tout, n refuse tout, 1 garde la règle 1, e1 la reformule.
  3. Vous
    y
  4. Assistant
    Règle enregistrée dans prompts/gen/learned.md. Elle sera lue au début de la prochaine demande.

Ce qu’elle cherche

Chaque constat porte un type, pour qu’une règle dise d’où elle vient. Il y en a six : error, correction, preference, workflow, gap et conflict. Sans --type, tous sont examinés.

  • 6types d’apprentissage
  • 3étapes : analyser, proposer, enregistrer
  • 40lignes de règles au plus dans learned.md

À quoi ressemble une règle

Chaque règle a les mêmes quatre parties : quand elle s’applique, ce qu’il faut faire, comment le vérifier, et pourquoi elle existe. L’exemple ci-dessous est une illustration, pas une règle d’un vrai projet.

Pourquoi le fichier reste petit

learned.md est lu au début de chaque requête, avec les règles fondamentales ; il doit donc rester peu coûteux à lire. Au-delà de 40 lignes de règles, /learn déplace le détail dans des fichiers ciblés, ouverts seulement quand leurs mots déclencheurs correspondent à la tâche.

À retenir

Aucune règle n’est écrite sans votre accord. Et aucun fichier Markdown ne peut obliger un modèle à le lire : sur Claude Code, le fichier est importé par l’hôte ; ailleurs, la règle figure dans AGENTS.md. /learn revérifie ce câblage à chaque exécution.

À essayer

  1. Installez ou mettez à jour la méthode avec le guide d’installation. /learn est distribuée depuis la 1.5.2 ; le fichier de règles est livré vide et les mises à jour préservent vos ajouts.
  2. Après une session où vous avez corrigé l’assistant, lancez /learn --dry-run pour voir les propositions sans rien écrire.
  3. Lisez chaque règle proposée, puis acceptez-la, reformulez-la ou refusez-la. Seules les règles que vous validez sont enregistrées.
  4. Plus tard, lancez /learn --review pour confirmer, retirer ou fusionner des règles.
