Quelle part de votre workflow a vraiment besoin d’un modèle ?

Faire passer une étape d’un prompt à un script la rend prévisible et gratuite à relancer. AI-KIDO 1.5.5 mesure ce passage : chaque étape est classée, et le workflow reçoit une part automatisée à faire monter.

Installer

Le workflow des notes de version de Camille fonctionne. À chaque version, un agent rédige les notes, un autre ouvre chaque lien, et elle relit. Mais chaque exécution coûte des jetons et quelques minutes, et la vérification des liens donne parfois un résultat différent pour la même page. Elle se pose une question simple : dans cette chaîne, quelles étapes ont vraiment besoin d’un modèle ?

L’idée en une image

Le métier a plusieurs noms pour ce passage. On parle d’IA compilée ou de distillation de workflow quand la logique d’un prompt est figée dans du code ordinaire, qui s’exécute toujours de la même façon, sans coût de modèle. DSPy et GenAIScript programment les prompts avec des entrées et des sorties typées au lieu de texte libre.

Quand un modèle reste dans la boucle, le décodage contraint garde sa réponse exploitable par un script. Claude et OpenAI proposent tous deux des sorties structurées qui suivent un schéma JSON.

AI-KIDO met une mesure sur ce chemin. Chaque étape d’un workflow entre dans l’une de trois classes, et le score est leur moyenne pondérée.

  • Déterministe · 1Un script, une commande, ou une décision prise par le moteur lui-même, comme un choix sur une valeur. Même entrée, même sortie.
  • Assistée · 0,5Un modèle qui doit renvoyer un schéma de sortie validé. Il écrit toujours, mais sa réponse peut être vérifiée par un script.
  • Ouverte · 0Un prompt libre, ou une décision humaine. Précieuse, mais ni prévisible ni gratuite à relancer.

Ce que fait Camille : mesurer, puis distiller

Elle demande le score de la version qu’elle utilise aujourd’hui. Le calcul n’appelle aucun modèle : il lit le workflow et explique chaque étape.

  1. Vous
    /workflow-score release-notes
  2. Assistant
    Part automatisée de release-notes 1.0.0 : 0,25 (méthode statique).
    Rédaction : ouverte, agent en prompt. Vérifier les liens : ouverte, agent en prompt. Liens OK ? : déterministe, choix sur une valeur. Relecture humaine : ouverte, décision humaine.

La réponse la surprend : vérifier des liens n’a besoin d’aucun modèle. Un court script peut ouvrir chaque URL et compter celles qui sont cassées. La rédaction, elle, a besoin d’un modèle, mais elle peut rendre ses sections dans un schéma qu’un script vérifie. Elle crée la version 1.1.0 avec ces deux changements et garde la relecture humaine.

Sous le capot, le score est le détail de chaque étape, avec sa classe et sa raison. Voici la sortie réelle pour la version 1.1.0 :

Le but n’est pas 100 %

La relecture humaine reste ouverte, et c’est voulu. Le score ne demande pas de supprimer le jugement ; il montre où un modèle est utilisé par habitude plutôt que par besoin. Une étape qui décide de ce que dit une version mérite un modèle ou une personne. Une étape qui compte des liens cassés mérite un script.

À retenir

Le score est statique : il lit la définition, n’appelle aucun modèle et ne donne aucune estimation de coût. Le même workflow obtient toujours le même score, donc un score qui change vient toujours d’un workflow qui a changé.

Dans l’aperçu de développement du Core Agent, une seconde mesure suit les exécutions réelles : elle compte les étapes réellement exécutées par un script et estime les jetons évités, une estimation et jamais une facture. Le score statique dit ce qu’un workflow permet ; la part mesurée dit ce qu’il a fait.

Deux règles derrière le score

La version 1.5.5 ajoute deux points durs que suit chaque agent AI-KIDO. Le premier, Code Economy, fait s’arrêter l’agent sur la route la moins chère qui couvre le besoin : pas de code, puis un actif existant, puis la plateforme, et seulement ensuite du code neuf. Avant d’écrire le vérificateur de liens, un agent cherche d’abord un script que le projet possède déjà.

Le second, Agent Economy, traite les jetons et les nouvelles tentatives comme un budget. Un appel en échec ne prouve rien sur les données visées : si le vérificateur de liens dépasse son délai, l’étape est signalée non vérifiée, jamais « aucun lien cassé ».

Pour l’autre face de la même idée, laisser les scripts faire ce qu’un script fait exactement, lisez notre article sur les outils déterministes.

Essayer

  1. Installez la CLI 1.5.5 : npm install -g @aikido-method/cli@1.5.5, ou suivez la page d’installation.
  2. Écrivez ou ouvrez un workflow avec /workflow-new, puis repérez les étapes qu’un script pourrait exécuter ou qui pourraient renvoyer un schéma.
  3. Avec un Tatami Core Agent configuré, tapez /workflow-score avant et après votre changement, et gardez les étapes humaines qui comptent.
