Installer

Votre équipe garde ses règles, ses personas et ses workflows dans une Memory Bank AI-KIDO. Une personne utilise VS Code, une autre un assistant en ligne de commande, et un agent de code tourne dans le cloud. Chacun a besoin des mêmes connaissances, et personne ne doit recevoir une copie périmée.

L’idée en une image

Kimono RAG MCP est un serveur MCP. En mode AI-KIDO, il prend un dossier racine contenant prompts/index.md ou index.md et expose cette Memory Bank, via le même petit jeu d’outils, à tout client qui parle MCP. La méthode devient quelque chose que les clients connectés peuvent chercher, et non quelque chose qu’il faut apprendre à chacun.

Choisir le mode

Trois façons de se connecter

  • Extension d’IDE (recommandée) : à installer depuis le Visual Studio Marketplace dans VS Code ou un IDE compatible.
  • Serveur Docker : un corpus partagé pour plusieurs clients MCP, dont l’agent cloud GitHub Copilot, via le point d’accès /mcp.
  • Installation native depuis les sources : un serveur stdio local pour un client MCP qui le prend en charge.

Pour l’agent cloud, vous ouvrez les réglages de votre dépôt, section Copilot, et vous y collez la configuration MCP qui déclare un serveur distant. Le jeton est enregistré comme secret des Agents, jamais dans le fichier.

À surveiller

Un serveur sur votre portable n’est pas visible d’un agent cloud. Docker Compose en local écoute sur la boucle locale et GitHub ne peut pas l’atteindre directement. Le point d’accès doit être joignable en HTTPS, protégé par authentification, et pointer vers une copie du dépôt que le serveur peut lire.

À essayer

  1. Choisissez une connexion dans le README du dépôt Kimono RAG MCP.
  2. Activez le mode AI-KIDO et pointez le serveur vers un dossier contenant votre Memory Bank.
  3. Posez à votre assistant une question à laquelle votre base peut répondre. Plus de détails sur la page Kimono RAG MCP.
