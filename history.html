The story of AI-KIDO

A way of learning to work with AI, built patiently and tested on real projects. The repository is the toolbox that grew out of it.

A method first. A tool second.

AI-KIDO began in January 2025 with a question: how do you learn to work with AI in a way that is reliable, repeatable and easy to pass on? The answers came from real projects. The repository arrived in May 2025, the first numbered version in November.

Born from a simple observation

Faced with the power of language models, many developers swing between wonder and frustration. AI-KIDO joins "AI" with Aikido, the way of the harmony of energies: instead of fighting an AI's limits, you learn to use its energy.

Aikido

Redirect, don't resist

Work with the model's strengths and channel its weaknesses, so the interaction stays balanced and productive.

Documentation first

Let documentation lead

From test-driven to documentation-driven development: what is written down becomes the first source of truth and guides every exchange with the AI.

Awase

One source of truth

Truth tables stay flexible and evolve with the project, while validated decisions are locked as firm foundations. You decide what stays open and what is settled.

Kokyu

Always breathing

Regular cycles of review and improvement keep the method alive, and lessons learned flow back into it.

The real challenge is not learning to use AI, but learning to dance with it. The spirit of AI-KIDO

A path, not a manual

AI-KIDO is taught like a martial art: step by step, with belts that mark your progress, from your first prompt to the most sophisticated orchestrations.

White belt

Foundations

Set up your environment and learn the eight principles that everything else rests on.

  • The eight AI-KIDO principles
  • A working environment and your first functional knowledge base
  • Structured prompts and expert personas
  • Data validation, tests and first optimizations

Outcome: You generate reliable code in your own technology from a structured prompt.

Yellow belt

Expansion

Master your assistant and get more out of every prompt, in any field and any technology.

  • The five specialized modes: Code, Architect, Debug, Orchestrator and Ask
  • Optimized prompts, with around 40% fewer tokens
  • An advanced Memory Bank and community patterns such as SPARC
  • Plugging external tools in through MCP

Outcome: You spend fewer tokens and pick the right mode for each task.

Orange belt

Mastery

Move from individual practice to a base shared by the whole team, with rules that hold.

  • A collaborative structure organized by roles, technologies and projects
  • Team standards and governance, with hard points that lock what is decided
  • Automatic synchronization of the shared base
  • Metrics and a dashboard to follow adoption

Outcome: The whole team works from a single source of truth.

Green belt

Professional practice

Theory becomes everyday practice, from kicking off a project to passing the knowledge on.

  • Katas to start a project, generate code, review, document and test it
  • Applications for each role and fully integrated workflows: CI/CD, Git hooks, automated validation
  • A persistent Memory Bank and multi-project orchestration
  • Complex problem solving, innovation and mentoring

Outcome: You are autonomous on real projects and able to train others.

Blue belt

Agentic industrialization

Once your production chain is mastered and stable, the next step is industrialization with autonomous agents.

  • Automated tests driven by specifications (SDD) and by tests (TDD)
  • Autonomous AI-KIDO agents working along your production chain
  • A new dimension for the developer, who guides the agents and dances with them
  • A system that opens up to several teams and several projects

Outcome: Your production chain runs with agents, under your direction.

Black belt

Continuous improvement

The whole system keeps getting better, and you help it along.

  • Fewer tokens spent and greater efficiency
  • Strict respect of the chain, from end to end
  • Constant innovation that keeps the method alive
  • Contributions back to the method itself

Outcome: You no longer only use the method: you make it evolve.

Patience, perseverance, humility, curiosity. The goal is not "AI that codes for me", but the augmented developer.

The same path also exists as a hands-on training in five workshops, from the first prompt to full autonomy, with exercises, corrections and a review of what was learned.

The repository: the method made tangible

The repository is not the starting point: it is the result. Knowledge base, personas, workflows, agents and commands exist because the method needed them.

Timeline

From the latest release back to the very first idea.

  1. 28 October 2026

    Version 1.5One knowledge base, nine assistants

    AI-KIDO is now packaged for Claude Code, Claude Cowork, GitHub Copilot and VS Code, Codex, Kiro, Zoo Code, Roo Code and Antigravity. Each distribution is generated from the same source, installed through a reviewable plan, and can be updated or removed while keeping the project's Memory Bank. /skill-manage now relies on a deterministic engine to search, install and update skills from a catalog and from trusted external sources. Choose your assistant and install.

  2. 25 October 2026

    Kimono RAG MCPLocal project context, now on the VS Code Marketplace

    Available on the VS Code Marketplace, Kimono finds useful passages in code and documents, with or without an AI-KIDO base. Its ambition: less unnecessary context, more productive work and better control of token consumption. Two research and planning trials measure 67.5% and 71.4% lower cumulative input tokens; explore the results and their limitations.

  3. 16 October 2026

    Kimono MCPThe Memory Bank opens up to connected clients

    With Kimono MCP, assistants can find the same documents, commands, personas and workflows in a shared AI-KIDO base. The method opens up to connected clients, making the team's knowledge easier to find and reuse.

  4. 3 October 2026

    Version 1.4The first public release

    The whole Memory Bank now has an English baseline, the project ships under an MIT license and its configuration is cleaner and safer. The method and its toolbox are open to everyone.

  5. 27 February 2026

    Version 1.3.3Skills with a full lifecycle

    Skills can now be created, installed, updated and removed. The Jira and Confluence integrations leave the core and are published as skills in their own repository, so the method stays lean and each capability evolves on its own. A complete technical analysis plan joins the toolbox, and the method opens up to contributions from the team.

  6. 16 January 2026

    Version 1.3.1Connected to team tools

    Project tools such as Jira and Confluence are explored and built in, then connected through MCP servers, a cleaner and more durable approach than embedded scripts.

  7. January 2026

    The 1.3 architecture

    A new organization gathers everything in one place. AI-KIDO becomes a real toolbox, with its own internal agents working together to maintain the Memory Bank.

  8. 1 December 2025

    Version 1.2.1Ready for Claude Code

    Compatibility with Claude Code is validated and consolidated, with a command that keeps the project's assistant configuration aligned with the Memory Bank.

  9. 21 November 2025

    Version 1.2The first numbered version

    A major restructuring for AI assistants: standard entry files for agents, creation and maintenance commands, a normalized base and the Light mode. The method is now ready to be used by others.

  10. November 2025

    The commands take shape

    A persona taxonomy and a persona creation command, then project initialization, automatic maintenance of the Memory Bank and agent compilation. The rules of the method are consolidated, the Light mode returns for smaller teams, and the method starts speaking the language of today's AI tools.

  11. October 2025

    Refocus: one method, not a collection of copies

    A deliberate strategic choice: stop keeping one copy of the method per project and concentrate everything in a single reusable Memory Bank. The project becomes lighter, clearer and ready to be shared.

  12. August → September 2025

    Training, publishing, observability

    A training course on design patterns and anti-patterns brings the concepts and techniques layers to life, and is published as a complete 44-page website. An observability project follows, built on the same principles.

  13. June 2025

    A shared foundation, new terrains

    The common base grows into a solid foundation reused by every project. The method is put to the test in a very different field: a fiction universe, to prove it works far beyond software.

  14. Late May 2025

    Teaching the tool to know itself

    The documentation of the assistant's own environment is embedded in the Memory Bank, so the AI can consult it and use its tools correctly. A first base on anti-patterns and a shared common base follow.

  15. 25 May 2025

    Beyond software

    The method leaves the world of code with a first project for primary school teachers: supporting pupils, adapting to special needs, preparing parent meetings. The core directories of the Memory Bank, hard points and specifications, appear.

  16. 16 May 2025

    First repositoryAI-KIDO gets a home

    A first complete toolkit arrives: four ready-to-use workflows (code generation, code review, documentation, project initialization) declined for more than a dozen technology stacks: PHP, Node.js, Java, DevOps and application audit.

  17. January → May 2025

    OriginsThe idea takes shape

    Before any tool, there was a way of learning: how to talk to an AI, how to give it a memory, how to make results repeatable. Truth tables, personas and workflows are designed and tried on real projects long before anything is published.

And now?

The story continues in the open. Try AI-KIDO on your own project, follow the releases and tell us what you build with it.
